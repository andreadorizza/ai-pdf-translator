# The agent orchestrates; the command-line program is its toolbox

The command-line program does all the work that needs no model: it sorts pages, runs OCR, finds blocks and doubts, finds term candidates, writes batch files, makes the scan crops, and builds the translated PDF and the review list. The coding agent orchestrates: it gives the term list and then each batch to a subagent, in parallel, and each subagent writes one translation file in a fixed format. The main agent sees only file paths and short summaries, so a long document never passes through its context. A headless mode runs the same steps through a translation service, for Colab, the self-test and scripts.

We first chose a program that also made the model calls and a skill that only ran it. We changed to this design because the users already have a coding agent: its subagents translate with the agent's own model and plan, with no extra API key, and running subagents inside the agent is ordinary use of it, whereas scripting the agent's command-line tool from a program is not what its terms favour. The file format between the steps keeps the result the same whichever agent, or the headless mode, does the translation.
